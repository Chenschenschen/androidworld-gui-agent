2 Context: prefix + trace
- Context: the model’s input for the current decision.
- Trace: The (historical) ordered record of user messages, assistant messages and tool results.
- Action space: The set of operations the agent can perform, constrained by available tools, valid arguments.
- Observation space: The set of possible observations the agent can receive through available interfaces.
Execute action: get_weather("Beijing", 09-18)
Key distinction: Calling a tool is an action. Its returned result is an observation, which can be appended to the next context.

=== PAGE 12 ===
3 Message format
12
• role: Identifies the message source.
• system: Application instructions for the 
model.
• user: The task and information 
supplied by the user.
• assistant: A model-generated reply or 
tool-call request.
• tool: A result supplied by the runtime 
for a tool call.
• content: Carries the message body.
• messages: An ordered array of messages.
• tools: All available tool definitions. A 
request-level array alongside messages. 
• It is not a message role.

=== PAGE 26 ===
5 Example: SKILL.md
travel-briefing/SKILL.md
26
---
name: travel-briefing
description: >
Prepare weather-based travel advice.
Use for a city-and-date travel briefing.
---
# Travel Briefing
1. Confirm the city, date and requested output.
2. Call get_weather with valid arguments.
3. Ground advice in the returned forecast.
4. If saving is requested, call save_note.
5. Check the result before reporting completion.
# Exception
If a tool fails, explain what remains incomplete.
For extra advice guidance, read references/advice.md.
- Frontmatter: when to use it. 
- Markdown body: steps and completion checks.
