KV CACHE
Attention
Each token forms a Query, Key, and V alue. A new token uses its Query to find relevant information from previous tokens.
• Each token produces a Query, Key, and Value.
• The new token compares its Query with the Keys of previous tokens, and gets a weighted sum of the Values.
• Each token can only attend to current and previous tokens.
Causal mask M
Rows are Queries. Columns are Keys.

=== PAGE 18 ===
KV CACHE
What the cache actually stores
The model is decoding one token at a time. It has finished t1 to t4 and is about to place t5. Ask what genuinely changes at this step.
Token positions
t1 t2 t3 t4 new t5
past — already computed current position
Recomputed at this step
one new column, and nothing else
q5 k5 v5
The Query is fresh every step, because the thing doing the looking is new.
Read back from the cache
everything to the left of it
k1 … k4 v1 … v4
These were computed from tokens that have not changed — and, by the 
causal mask, cannot change.
q5 compare with k1 … k5 weights weighted sum of v1 … v5 z5 one step
The past does not change, so its Keys and Values do not change. Store them once, append one column per step. That is the 
entire idea — and the reason a stable prefix is worth money.

=== PAGE 19 ===
KV CACHE
KV Cache
KV cache removes repeated projection work
Without KV cache
Every decoding step forwards the whole prefix again.
step 1    compute K₁ V₁
step 2    recompute K₁ V₁ +  compute K₂ V₂
step 3    recompute K₁ V₁ K₂ V₂ +  compute K₃ V₃
step 4    recompute all earlier K/V  +  compute K₄ V₄
With KV cache
Read the stored history and append one new K/V pair.
step 1    compute and store K₁ V₁
step 2    read cache  +  append K₂ V₂
step 3    read cache  +  append K₃ V₃
step 4    read cache  +  append K₄ V₄
A context-design rule: keep the prefix stable so the cached prefix states remain reusable
https://huggingface.co/blog/not-lain/kv-caching

=== PAGE 23 ===
Cache-Friendly Design Principles
1 Fixed Early Content
Once the system prompt, the tool definitions and their order are set, leave them alone for 
as long as you can.
2 Append dynamic information
Time, status and task progress belong at the end of the message list, never at the top.
3 Keep the standard structure
Let the chat template render roles, boundaries and tool results. Hand-formatting saves nothing 
and breaks the cache.

➢ Maintain the status bar with code whenever possible

➢ Do not delete the original context
